# 前端设计

更新：2026-10-26。本文定义重构后的目标交互，代码迁移状态见 [规范入口](../README.md)。后端接口见 [桌面后端设计](../backend_spec/backend.md)。

当前实现：编辑/装配/演示入口及旧 scene.* 桥接已删除；已接入真实 GLB 加载、原始层级/颜色/位置、对象树及画面双向选择、同来源复用、重启恢复和失败重载。CAD 几何仍为只读；已接入整机旋转与平移的保存回显，不引入对象级场景编辑或模拟执行器。已接入按轮次折叠的执行过程、真实工具参数/结果详情、公开思考文字及显示开关，沿用 durable 历史。模型旁可选择原生支持的推理档位，回复支持流式与历史 Markdown 渲染。

## 1. 第一阶段范围

保留当前简约桌面外观、项目导航、聊天和设置。场景搭建第一阶段只完成：选择项目中的 STEP → 对话触发模型调用 CAD MCP → 显示真实结果 → 查看、选择与重新打开。

移除建模、分组编辑、颜色/位置编辑、参考系、关节、配合、运动预览、URDF 导出及场景版本恢复入口。保留 CAD 工具不代表为每个工具建设前端编辑面板。预置机械臂示例退出正式导入流程。

## 2. 布局与视觉

| 区域 | 内容 |
| --- | --- |
| 左侧 | Dai、可折叠项目及项目下对话、紧凑底部工具条 |
| 通用对话主区 | 消息及底部输入框 |
| 场景搭建中间 | 三维视口；左侧可折叠对象树，顶部少量查看操作 |
| 场景搭建右侧 | 同一条对话的消息及输入框 |
| 设置 | 独立设置视图，提供返回工作台 |

采用黑白灰、低对比选中、清楚的缩进和留白；保留模型原有颜色。图标统一使用现有 Lucide，菜单和提示复用现有 Radix。主题支持浅色、深色和跟随系统。欢迎区保留“今天想和呆呆完成什么？”及简约 D 角色。

进入场景搭建立即显示空视口，不要求先选 STEP。选择模式或文件不自动请求 LLM、不自动解析。输入框的当前 STEP 从项目目录选择，不上传、添加或复制文件；多个文件时选择其一。

保留可拖动分栏、项目栏折叠和窄窗口的场景/聊天页签；尺寸与顶栏避让沿用当前已验证行为。页签切换不销毁同一模型。

## 3. 项目与对话

- 项目对应规范化真实目录；同目录复用项目身份，同名不同目录分别管理。项目可包含任意内容。
- 项目下可有多个 STEP 和多条对话。对话保存自己的上下文、草稿、模式、模型和 STEP 关联。
- 同项目、同 STEP 的对话查看同一份最近成功导入结果；切聊天不回滚模型。
- 保留新建、重命名、归档、恢复与产品层删除；删除采用菜单内“删除 → 确认删除”，不物理清除 durable 历史。
- 移除项目仅改变导航可见性；保留文件和聊天，重新打开同目录恢复原记录。

## 4. 导入与显示

1. 用户选择当前 STEP，发送解析/导入请求。
2. 聊天展示实际工具名称、运行状态和服务进度；允许模型按 Skill 自行决定下一次调用。
3. 只获得 CAD 文档或 job 时，视口继续保持原画面或空态。
4. 后端发布已持久化的 ImportedModelRef 后，前端获取模型清单和资源。
5. 使用 Three.js 加载 GLB、原始对象结构与映射，按包围盒适应视角，显示原始颜色与实例位置。
6. 有有效网格的部分结果正常加载，视口简短提示“部分显示 · N 个 CAD 面未显示”，不宣称几何已修复。完全无网格的对象保留树条目并标注“未显示”。计数按唯一几何面统计，重复实例不重复累计。
7. 显示成功与显示失败属于前端状态；工具的几何计算结果保持真实记录。

前端依赖结构化模型引用，不从助手文字、工具名称或“解析成功”文本推断资源。显示格式和对象映射见 [CAD MCP 设计](../mcp_spec/cad-mcp.md)。

useImportedModel 订阅 display.changed 并查询 display.get；同一 importId 不重复创建 GPU 模型。model.ts 读取受控 URL、核对文件大小/hash，复用 GLTFLoader 解析并应用清单的 displayToScene；ObjectTree 与网格拾取共用 CAD objectId，保留重复实例身份。新模型准备完成后才替换旧模型，取消的异步加载不能覆盖新目标，释放模型时去重销毁共享几何和材质。

查看操作包括旋转、平移、缩放、适应模型、等轴/前/右/顶视图、对象选择及透明度。Z 向上，前视沿 X 轴观察，观察正负方向与坐标提示统一。对象树与画面选择双向联动；单个对象可关联多个网格，重复实例分别选中。装配树缺失时允许多个平铺根。

选择使用网格 Raycast，不用包围盒拾取；选中反馈为实体表面染色与柔和发光，取消包围框。悬停使用较弱的表面预高亮，拖动视角时不做悬停拾取，指针移动最多每帧执行一次 Raycast；不增加边线几何或额外轮廓渲染通道。

对象树下方显示当前对象名称、0–100% 透明度滑块与重置。父装配调整统一作用于子实体，并清除其已有子对象覆盖；子对象随后可以单独调整，重置恢复原始材质透明度。选中项在 100% 透明度下仍保留弱可见高亮，未选中且完全透明的网格不拦截拾取。隐藏对象树时保留已选对象的属性区。

透明度按 importId / objectId 保存在前端，既不改 STEP 或 GLB，也不写后端版本。appearance.ts 管临时克隆材质；保留共享原始材质，对象不再需要高亮和透明度覆盖、替换模型或卸载时恢复并释放克隆。model.ts 在加载时捕获原始几何与材质，卸载只释放自己拥有的原始资源，避免材质被替换后遗漏原引用。深浅主题变化复用现有克隆，不累计染色。

## 5. 状态及生命周期

前端复用共享的 ImportedModel 类型；查看状态集中在视口模块的 types.ts，至少区分 empty/loading/ready/error，包含 importId、选中 objectId、相机及对象树展开状态。工具进度来自 Harness 投影，避免另建一套任务状态机。

| 场景 | 行为 |
| --- | --- |
| 同一 STEP、同一 importId 切聊天 | 保留 GPU 模型、相机、选择与透明度，只更换聊天上下文 |
| 切到通用对话或设置 | 隐藏视口，保留当前模型；不调用工具 |
| 切到其他项目或 STEP | 解除旧加载和订阅，释放旧 GPU 资源，读取目标的最近成功结果 |
| 切回原来源或重启应用 | 加载已保存结果；相机不保证跨来源或重启恢复，不重新解析 |
| 同 importId 定位更新 | 复用当前 GPU 模型、相机朝向、选择和透明度；外层组应用已保存 translation/rotation，重新适应模型 |
| 同来源产生新 importId | 加载新结果，清除旧选择和透明度覆盖；失败保留原成功画面及查看状态 |
| 资源加载失败 | 明确显示错误，可重载已保存资源；不重新发送消息或重跑 CAD |
| 源文件变化/失联 | 已保存模型可查看；提示显示的是旧版本，重新解析须由用户发起 |

场景产物保存在用户数据目录。若数据库记录指向不可用资源，视口说明资源不存在或无法访问；重新加载仅重试读取，不自动解析 STEP。已有画面遇到新资源读取失败时保留。旧项目内产物不自动迁移；用户可选择重新导入。存储边界见 [后端设计第 14 节](../backend_spec/backend.md#14-用户目录场景存储)。

运行中切项目、STEP 或对话须先停止并等待真实清理；同一前台 Run 内不并发手工修改。关闭到托盘保留任务和界面，真正退出交给后端统一清理。

## 6. 设置与桌面基础功能

| 页面 | 保留内容 |
| --- | --- |
| 常规 | 主题、思考摘要显示开关、实际支持的语言/显示设置 |
| AI 设置 | 提供方、API Key 或账号登录、服务地址、模型目录、默认模型、启停和移除 |
| 工具与技能 | 按业务模式及全局/项目分区；内置展示 cad-mcp、alignment-mcp，以及 scene-building / scene-alignment Skill |
| 本地数据 | 实际用户数据位置、归档/恢复说明；未实现的备份/清理不显示为可用 |
| 信息与快捷键 | 版本、许可、现有固定应用内快捷键 |

pi-ai 中的提供方和认证能力按实际 SDK 目录呈现；配置模型与实际调用分别验证。保留当前真实登录、凭据暂存/保存及安全存储反馈，不展示秘密值。MCP 配置继续支持 stdio、Streamable HTTP 和真实工具发现；技能继续支持正文编辑和范围选择。

工具清单仅显示英文名称和一句用途，不显示 Schema、JSON 示例、句柄类型或执行顺序。技能提供工作说明；启用技能不等于工具已运行。

保留一体化原生顶栏、拖动区域、Tray、单实例恢复、系统主题和 Ctrl/Cmd 加减缩放；Linux/macOS/Windows 使用同一套 Electron 原生能力，目标平台分别验收。

两个内置基础 Skill 在工具与技能页显示“随模式加载”，取消其启停开关；文件缺失显示“技能文件缺失”。MCP 工具与用户自定义 Skill 仍可独立启停。场景首次请求加载实际技能正文，通用对话不携带场景 Skill。read 的目录调用摘要显示“对象目录 · 整页读取”或“对象与几何参照 · 整页读取”，完整绝对路径保留在提示和参数详情中。原有返回预览截断只影响 UI，不裁剪发送给模型的实际读取结果。

## 7. 前端代码及验收

前端纯逻辑测试集中在 `tests/renderer/`，真实 Electron 交互测试在 `tests/integration/`；不在组件或场景源码目录中放置测试。测试目录规则见 [规范入口](../README.md)。

- 页面组件只组合布局；项目/聊天、设置和模型查看分别管理状态，资源加载与 Three.js 对象创建分开。
- 导入结果只读；相机、选择、透明度和树展开留在前端，不为查看动作写场景版本。
- 防止过期异步加载覆盖新来源，卸载时释放订阅、网络请求和 GPU 资源。
- 验收真实 STEP 的颜色、位置、单位、对象树、重复实例、点击映射及首次渲染；空模型和不完整模型有明确反馈。
- 验收同源切聊天、跨源返回、重启、失败保留旧画面和资源重载；这些过程不重放 CAD 工具。
- 覆盖共享材质隔离、父子透明度覆盖、多材质恢复和克隆释放；真实桌面验收选择、滑块、主题切换与新产物重置。
- 登录、模型选择、草稿、归档、删除、项目移除、托盘、缩放和窄窗口布局不得因后端重组失效。

整机对齐由聊天触发真实 MCP 调用，前端不自行计算或提前平移。display.get 返回的 placement 独立于 CAD manifest.displayToScene，视口按 `Placement × displayToScene × 原对象局部变换` 组合显示。定位更新复用网格，只调整外层组与相机；同来源切聊天及重启恢复保存的旋转和平移，新 importId 默认原坐标。

## 8. 旋转回显与后续模型观察

整机旋转回显已接入；选中项发送和截图仍待后续实现。保持现有布局，不新增技术参数面板。CAD 文档每个 Run 结束后释放不影响已加载画面；后续对齐读取本地产物。原 STEP 变化或缺失时仍可对当前保存版本操作，保留版本提示，不自动重解析。

- 后续用户发送时，向后端附带当前视口的 importId 与选中 objectId；后端校验归属后注入 scene-context。没有选中对象即为空，不能假设“它”必然指某个实体。相机、透明度仍是查看状态，不因发送消息写定位版本。
- 结构化对象树、局部变换、当前 Placement 和 CAD 特征是模型理解几何的基础；**LLM 不会因前端已渲染就自动看见画面**。read 读取这些文件无需用户逐次确认。文件入口在模型上下文中提供，工具与技能页面仍仅展示名称及简短用途。
- 后续可增加桌面观察工具 `viewport_capture`：在当前视口完成渲染后获取截图，返回已登记图片路径、importId、定位 revision 和相机参数，由现有 Pi read 读取。它属于桌面视图能力，不塞进 CAD/Alignment MCP；生成与读取图片是两个职责。仅在实际图像模型可用时提供图像观察能力，文本模型使用结构化数据。
- 截图必须绑定捕获时的模型与 revision；目标不匹配或视口不可用时明确失败，不把旧图/黑图当成当前模型。截图临时保存、不加入不可变 CAD 产物；不持续抓屏、不自动改变用户相机，也不宣称一张图包含全部遮挡结构。多视图观察另行按需要扩展。
- 定位回显沿用 display.changed → display.get；视口外层组同时设置 position 与 quaternion，顺序仍为 `Placement × displayToScene × 原对象变换`。不得把用户旋转和 GLB 坐标转换混为一体；同 importId 复用 GPU 模型、选择和透明度，并更新相机适应范围及裁剪面。
- 前端不在工具调用前猜测结果、不负责权威保存；失败保留原姿态。重启读取后端保存的同一绝对变换。将来若增加手动位姿编辑，必须提交同一定位契约，不独立修改 artifacts 或绕开版本校验；本阶段不开发该编辑器。

验收：没有活 CAD 文档时跨 Run 定位；旋转和平移的屏幕位置与保存数值一致；同来源切聊天/重启恢复；新旧 importId 选择不串用；缺少图像能力仍能用文本特征对齐。可选截图失败不阻断普通聊天与结构化工具调用。

## 9. 对话过程展示

借鉴 PI-Desktop 的 TurnProcess、工具摘要和 ThinkingRow 交互，接到现有 pi-durable 事件与原生历史。一次用户发送对应一个过程分组，最终答复保留在分组外；不创建另一份聊天记录或执行状态机。

- 过程标题展示真实运行阶段、工具次数、异常次数及有依据的耗时。运行时默认展开，完成后默认收起；用户手动开合优先，流式刷新、卡片完成与父级折叠不得重置选择或抢走阅读位置。
- 工具行显示英文工具名、关键参数摘要、状态和耗时。read 展示文件名与请求行范围，展开显示完整绝对路径、参数、返回预览和错误；实际调用仍使用绝对路径，不通过展示缩写修改参数。CAD/Alignment 提供少量语义摘要，未知 MCP 使用通用参数与输出详情。
- 工具计算成功但桌面接管显示或定位失败时，工具行显示失败，详情同时保留计算结果和接管失败说明；不提示用户盲目重复计算。
- 输入参数来自 durable 工具开始事件及对应 assistant toolCall，不按工具名称猜测。历史关联按消息顺序和调用身份处理，避免不同轮次复用 callId 时串参数；缺失参数明确不可用。运行行与完成行使用相同调用身份更新，不重复计数。
- 公开思考文本来自 Pi thinking 内容块与流事件，按真实顺序放入过程内，支持流式展开查看。没有返回文字时只显示实际状态；redacted 内容和 thinkingSignature 不进入前端，不还原隐藏内容。
- 常规设置增加“显示思考摘要”，默认启用，内容默认折叠；开关仅影响展示，不改变模型推理模式，也不删除原生历史。
- 工具输出、参数和思考文本使用有界预览，截断明确标记；敏感参数字段遮蔽。等待、回复、思考、执行、重试、压缩、失败和停止区分展示，不伪造百分比。历史没有时间数据时省略耗时。
- 后端在现有 projection 中补齐展示字段，共享 Schema 同步校验；前端用纯函数按用户请求组织消息，组件分别负责过程、工具详情、思考摘要和答复。复用现有图标、颜色、折叠控件和设置，不移植 PI-Desktop 的 store、子智能体或插件 UI 框架。

验收覆盖工具参数与输出预览、真实 read 路径/行范围、未知 MCP、流式思考与 redacted 过滤、同名调用和跨轮次 callId 复用、历史/快照/重连、失败后恢复、停止清理、开合选择与窄窗口布局。使用本地模型协议对端，不消耗个人账号；已有登录、CAD 保存与回显保持可用。

## 10. 推理档位、Markdown 与连续场景任务

- 模型选择旁增加推理档位选择，复用 pi-ai 的受支持档位；只显示当前模型实际提供的选项。已有会话默认沿用原来的关闭状态，不支持推理的模型显示关闭且不可调。档位存入 durable 原生 AgentDoc，通过会话元数据投影给前端，不再复制一份推理配置。切模型时由 SDK 校验并归一化；选择完成显示实际生效的档位，运行中的请求配置不变。
- “显示思考摘要”仍仅控制展示。启用推理后可正常调用工具；推理文字是否返回由模型及服务决定，不将执行说明伪装为思考内容。不照搬语义不同的 omit 选项。
- 模型回复（含流式正文、执行说明和公开思考文字）使用同一个 Markdown 组件，支持标题、强调、列表、引用、GFM 表格与代码块。用户输入和工具参数/结果保持原文。表格及代码块在自身区域滚动，适应深浅主题与右侧窄聊天栏；历史重新打开使用同样的渲染。
- 使用 react-markdown 与 remark-gfm，不手写 Markdown 解析器或通过 HTML 字符串注入页面。禁用原始 HTML；外部图片暂不加载，链接仅允许 http/https 并通过桌面统一入口打开系统浏览器。
- “解析并旋转/对齐”允许在同一用户请求内连续完成。资源成功发布后使用新 importId；相互依赖的定位调用逐次取得提交后的 revision，不在同一模型回复中预生成多次修改。单次参考系对齐可以满足目标时优先使用现有 alignment_align_frame；只请求解析时不自动改姿态，未知朝向不凭包围盒尺寸推断。
- 修复与验收：推理参数实际进入服务请求，档位切换/会话隔离/重启恢复正确；Markdown 表格真实生成 DOM、流式和历史一致、无横向撑破；组合导入/旋转/归零经 Harness 真实执行并回显。过期 revision 返回当前定位供重算，不静默替换参数或重复执行相对旋转。

## 11. 场景问答的操作边界

进入场景搭建模式后仍可正常提问。“这里有什么/是否有机械臂/解释已有结果”默认查看保存的信息；对象编号不是语义识别证据，当前画面与选中项未自动提供给模型时需如实说明。普通查询不应触发重新生成显示资源。

为精确 CAD 计算重新打开原文件属于临时查询：当前画面、选择、透明度和保存定位保持原状态。结束查询/释放文档后仍可继续查看；原文件失联不阻断已有场景的数据问答。选中对象发送与按需截图另行实现，本轮不新增入口。
## 12. 聊天图片输入

普通对话和场景搭建均可通过图片按钮、粘贴或拖入添加图片；STEP 选择入口保持独立。发送前可预览和移除，支持图片与文字一起发送或单独发送图片。每次最多 3 张，单张不超过 5 MiB，总计不超过 10 MiB，支持 PNG、JPEG 和 WebP。仅图片输入模型可发送，其他模型保留草稿并提示切换。用户消息和历史中显示图片；视口截图作为后续独立入口。

Shell 命令等待确认时，在对应会话的聊天区域展示完整命令、工作目录、权限说明与确认/拒绝按钮；不遮挡场景视口。长命令可滚动查看，确认前不得执行，拒绝或停止后移除确认卡片。
