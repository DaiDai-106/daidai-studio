# 仓库代码规范

本文约定仓库主要语言的命名、排版和可读性；新增代码遵循这些规则，修改现有文件时保持上下文一致，不为统一命名而大规模重命名已有接口和文件。

## 通用原则

- 名称准确表达职责和单位，优先使用项目已有术语；缩写只用于团队熟悉的概念，不通过冗长名称弥补复杂逻辑。
- 同级函数、类方法和较长的对象方法之间留空行；函数内按校验、准备、处理和返回等逻辑阶段分组，相关语句保持相邻，不逐行插空行。
- 注释以中文为主，解释所有权、边界、单位、并发和不直观的取舍；不重复代码字面意思，也不为每个函数机械添加注释。
- 在用户输入、跨进程通信、文件系统和第三方调用等边界做必要的校验与错误处理；信任已建立的内部约定，避免重复校验、无依据的兜底和过度防御，不用静默失败掩盖问题。
- 按实际需求抽取公共代码，避免为单一调用预建抽象。整理格式不改变行为；需要拆分职责时另行实施并验证。

## TypeScript、TSX 和 JavaScript

- 使用 2 个空格缩进，行宽以 100 列为准，遵循现有 Biome 格式；不使用 Tab 缩进。JavaScript 脚本沿用相同的排版与命名习惯。
- 变量、函数、方法和普通对象字段使用 `camelCase`；类型、接口、类和 React 组件使用 `PascalCase`；真正固定的常量可使用 `UPPER_SNAKE_CASE`；React Hook 使用 `useXxx`。
- React 组件文件使用 `PascalCase.tsx`；普通逻辑文件沿用所在目录的命名习惯，脚本和测试文件可使用 `kebab-case`。对外协议字段遵循对应协议，避免为本地命名改写第三方数据格式。
- React 组件按状态与引用、派生数据、effect、事件处理和渲染等职责分组，不为形式调整执行顺序。紧密配对的 schema 和由其推导的类型可以放在一起。
- 类型应准确表达可能为空或失败的情况；优先复用已有类型与契约，避免不必要的 `any`、断言和重复定义。

## Python

- 使用 4 个空格缩进，不使用 Tab；遵循 PEP 8，行宽以约 100 列为参考，长表达式按可读性换行。运算符两侧和逗号后保留空格。
- 模块、变量、函数和方法使用 `snake_case`；类使用 `PascalCase`；固定常量使用 `UPPER_SNAKE_CASE`；仅供模块内部使用的名称可加前缀 `_`。
- 顶层函数和类之间留两个空行，类内方法之间留一个空行；函数内部按逻辑阶段适当分组。导入按标准库、第三方库、本项目模块分组。
- 明确记录几何数据的单位、坐标空间和重要边界；遵循原有异常契约，不用宽泛异常捕获掩盖失败。

## CSS、HTML 和 SVG

- CSS 使用 2 个空格缩进；类名和自定义属性使用 `kebab-case`，声明冒号后留空格，规则块按组件或职责分组。复用现有设计变量，避免无依据增加全局选择器。
- HTML 使用 2 个空格缩进，优先使用语义化标签；属性和无障碍信息应与实际功能一致。
- SVG 保持有效的 XML 结构、必要的 `viewBox` 和可访问语义；图标文件命名沿用资源目录的既有习惯。

## JSON 和 Markdown

- 手写 JSON 使用 2 个空格缩进和双引号，不添加注释；`package-lock.json` 等生成文件由对应工具维护。
- Markdown 的标题、段落和列表之间留必要空行，代码块标注语言，链接使用可验证的相对路径；文档区分现有实现、目标和未完成事项。

## 检查范围

`npm run lint` 使用 Biome 检查当前配置覆盖的 TypeScript、TSX、`.mjs`、CSS、HTML 和 JSON（不含 `package-lock.json`）；`npm run typecheck` 检查 TypeScript 类型。Python 开发环境可通过 `python -m pip install -r requirements-dev.txt` 安装 Ruff，再运行 `npm run lint:python` 检查格式与基础错误。工具不会自动判断按职责分组的空行；仍需人工审阅和适用测试，不把工具通过等同于代码可读性或行为正确。
