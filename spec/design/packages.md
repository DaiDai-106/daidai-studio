# Package、Skill 与第三方能力目标设计

状态：目标设计。Dai 复用 Pi package 格式；内置 Runtime 与外部 Pi package 的装配不能假定由 Pi 自动完成。相关交互见 [前端](frontend.md)，SDK 可行性见 [测试与验收](testing.md)。

## 内置业务包

参考 Kinex，根目录 `packages/core` 提供通用 Runtime、工具和 Skill 装配；`packages/scene` 提供场景业务及自己的 Python 实现和 Skill。只有确实有共享 Python 功能才在 core 引入相应目录，不创建空模块。其他业务包按需求增加，不为每个用户项目生成源码包。Pi Extension 注册工具并桥接到项目 Runtime，取消和用户询问应从会话传递到执行上下文。

## 外部 Pi package 与 MCP

第三方能力以 Pi package 格式从支持的本地目录、npm 或 Git 来源安装；一个包可提供多个 Extension、工具或 Skill。包中 Extension 可以注册 MCP 服务，Dai 在该包上下文中展示来源、配置和连接状态；不提供脱离 package 直接添加 MCP 地址或命令的入口。Pi SDK 内置 MCP 连接能力需显式装配；默认 `mcp.json` 发现须隔离或受控，不能绕过上述入口。仅在包内放置 `mcp.json` 不代表服务自动注册。

Pi package 是资源分发格式，不能假定任意包自动支持 Dai 的凭据、桌面交互或自定义 Runtime。Dai 需要明确用户配置和凭据如何提供给包，追踪 Extension、服务与工具的所属来源，处理同名、更新、失败和运行中停用。Extension 可在宿主进程运行代码；工具过滤不构成进程沙箱。安装、启用、会话加载、MCP 实际连接和工具运行是不同状态，不能混同。

当前桌面扩展交互桥支持 `confirm`、`select` 和单行 `input`，会话停止或应用退出会取消等待；终端自定义组件、多行编辑器、主题与部分状态/通知接口尚未实现或不会显示，不能宣称所有 Pi 交互扩展都已兼容。

Pi 本地目录来源可能引用原路径，移动或删除会影响加载；npm/Git 来源的具体依赖和更新按 Pi 行为验证。用户配置和敏感凭据不写包源码；移除包不静默删除用户的项目、场景或凭据。旧架构配置不要求迁移。

更新由用户显式触发，可能联网。Pi 的更新可能同时作用于同来源的全局与当前项目包，跨作用域更新不是事务；某一项失败时应刷新实际状态并提示可能部分更新，不能承诺全部回滚。本地 Git 仓库及本地 npm registry 的安装、更新、隔离和单项失败已实测；远程认证、代理及真实网络尚未验证。

Pi 当前默认调用系统 `npm` 和 `git`，因此 npm/Git 来源分别需要目标系统提供对应工具；本地目录来源不需要。Electron 自带运行时不代表目标系统自动安装了 npm 或 Git。

当前 Pi package 安装和更新没有接入可取消句柄；应用正常退出会等待正在进行的安装或更新完成，遇到网络或 npm 脚本长时间挂起可能延迟退出。不得声称退出能中断第三方安装；后续需要 SDK 可取消接口或可安全终止并恢复的独立安装进程。

## Skill

参考 Kinex：从内置包和用户来源发现标准 Skill 目录，向模型提供名称和说明，按需加载 `SKILL.md` 正文及资源基目录。模式决定系统提示词和注入的 Skill，不同模式不串用；Pi 原生 Skill 加载与 Dai 的发现机制须明确分工，避免重复。前端支持新建、编辑和完整目录导入；包内 Skill 默认只读，直接复制入口尚未实现。Skill 目录保留 frontmatter、相对路径、脚本和附件。

当前实现将用户导入的 Skill **完整目录复制**到 Dai 数据根，保留原目录不变；Pi package 的本地目录来源则按 Pi 的方式引用原路径。用户 Skill 可编辑，包和内置 Skill 只读。包启停按全局或项目 ID 管理；多个来源同名的最终优先级仍需明确。用户项目内不创建 `.dai/`。

包中 Extension 可通过 Pi 的 `registerMcpServer` 注册服务；Dai 显式装配 Pi 的 MCP 连接器，同时禁用独立 `mcp.json` 的读取。第三方 MCP OAuth 状态与模型凭据一起保存在数据根的 `auth.json`。**桌面端的第三方 MCP OAuth 登录交互尚未打通**，不同包的权限和界面能力仍需按实际扩展逐项验证。
