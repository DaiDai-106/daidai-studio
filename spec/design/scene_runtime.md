# 场景 Runtime

本文描述场景 Runtime、提交与资源读取的当前实现和明确边界；URDF 导出未实现。总体架构见[后端与数据](backend.md)。

## 所有权和调用

业务 Runtime、Agent 工具适配和具体实现分离：`packages/core` 管理实际需要复用的通用能力；`packages/scene` 提供场景能力及其 Python 实现。Node 场景 Runtime 是进程内对象，按 Dai 项目 ID 获取，不按会话或 cwd 合并。宿主为场景会话注册工具，工具以项目身份调用场景服务；桌面手动操作也通过场景服务修改和提交。需要 Python 的导入和距离计算由场景服务调用 Runtime，距离计算可传入取消信号。

Runtime 管理自身工作、资源和计算进程。Python 负责场景几何计算，用户交互属于前端/宿主。未接入的旧视口截图和预设视角接口已移除；当前视口提供轨道交互和适应模型，不向模型自动提供画面。场景能力直接由 Python 实现，第三方 MCP 通过 Pi package 接入。

不为所有项目在应用启动时创建 Runtime 或 Python worker。场景显示可从持久资源恢复；真正计算时才按需创建 Runtime 和 worker。同一项目的会话复用该项目 Runtime 和 worker；当前 worker 空闲默认五分钟后停止，后续计算时再启动，不影响已保存场景。切会话不擅自停止共享 Runtime，不同项目的数据和任务相互隔离。

## 数据结构与提交流程

场景以项目 ID 和递增 `revision` 标识当前版本。存储的 document 包含 `models` 和可选 `joints`；对外 `SceneView` 增加项目 ID、revision 和计算出的源文件状态。完整契约见 `src/contracts/application.ts`，持久模型和投影见 `src/backend/scene/scene_service.ts`。

| 结构 | 主要内容 |
| --- | --- |
| 模型 | ID、源 STEP 路径和 SHA-256、源状态、GLB 资源身份/大小、对象、警告和完整性标记 |
| 对象 | ID、父对象、名称、可选 glTF 节点、基础及当前局部变换、局部几何边界、删除标记和圆柱面候选 |
| 关节候选 | 父子对象引用、类型、可选父坐标系轴线、依据版本、草稿/确认状态、有效性；限位为 `unknown` |
| 变换与边界 | 位置为米，旋转为 `xyzw` 四元数；几何边界为对象局部坐标，世界边界按当前层级计算 |

桌面导入经文件选择/拖拽授权后调用场景服务；服务让 Runtime 生成暂存资源，校验并接管后以预期 revision 提交数据库，再推送更新。变换、删除及关节操作也经服务提交；revision 不匹配时拒绝写入。选中项目后可直接从已提交文档和资源恢复视图，无需重放聊天。

## 进程和资源

Node 与 Python worker 通过标准输入/输出的逐行 JSON 通信：请求包含 `id`、`method` 和 `params`，响应以相同 `id` 返回 `ok` 和结果或错误。目前 worker 处理 `scene_import` 与 `scene_measure_distance`；协议没有版本字段，也不推送计算进度或接收取消消息。OCCT 诊断重定向到 stderr，避免混入响应。

同一项目请求串行执行：取消排队请求不会停止正在运行的任务；取消运行中的请求会停止该项目的 worker，后续请求按需重建。worker 异常退出或返回无效消息时，相关请求失败，不自动重放副作用。大型几何资源通过受控文件交付；已提交场景仍是权威来源。

当前 worker 的单条 JSON 响应上限为 8 MiB，按 UTF-8 字节计算；STEP 源文件与生成的 GLB 各限 256 MiB，单次导入限 10 万对象、去重几何网格合计 200 万三角形和 256 层。响应包含对象元数据，复杂模型可能在达到对象数上限之前先触及 8 MiB。超过限制会报错，不提交场景。真实 STEP 回归使用一个方盒的 5000 个重复实例，验证了 5001 个对象导入、超过 1 MiB 的响应契约校验、持久化和重启恢复，源文件哈希不变；该测试不能保证任意复杂的 5000 对象模型都满足响应上限，也未验证该规模下的 Electron 界面性能。更大规模需要后续评估分页或受控文件传输。

外部 STEP 原路径需有授权、类型及内容版本校验；读取期间改变或重新定位到不同内容不能当作原版本。对象和重复实例、源文件版本、坐标系和单位需要稳定定义，重新导入不可假设对象身份自动不变。前端展示与 Agent 所读结构均来自一致的场景版本；版本过期时拒绝写入并报错，调用方需重新读取当前状态。

用户可通过文件选择器重新定位源 STEP。后端对所选文件计算 SHA-256，仅与原内容一致且场景版本未变化时更新路径；模型身份、对象位姿及关节保持不变，源文件不复制。校验期间检查文件身份和修改信息，源文件后续再变化时精确计算仍会拒绝。列表中的源状态依据文件大小与修改时间判断，并非每次都重新计算哈希；精确计算和重新定位另做内容校验。当前不提供不同内容的自动映射。

同一项目的 STEP 导入和会话运行互斥：导入期间发送会被拒绝，会话运行期间开始导入也会被拒绝。取消导入或会话完成后可继续；不同项目互不阻塞。这样会话不会在导入尚未完成时将旧场景当作导入结果。

### 暂存写入和平台限制

Python 直接从 OCCT 的三角网格编码 GLB，OCCT 不再按可替换的暂存路径创建 GLB 或 `.bin.tmp`。POSIX 平台逐级使用目录句柄和 `O_NOFOLLOW`，以 `O_EXCL` 创建暂存文件，通过已打开的文件句柄写入，并通过目录句柄验证、重命名和清理。自动回归在写入前及重命名前分别把暂存项替换为指向外部文件的符号链接和硬链接，验证外部文件未被覆盖且导入失败。目录被替换时也会拒绝提交。这解决了原 OCC 路径重定向造成的外部文件覆盖，不代表抵御可修改进程内存或持有更高权限的攻击者。

资源接管通过固定目录句柄和文件句柄校验并复制产物，再以排他方式发布，避免校验后的目录或文件替换造成外部文件删除或错误内容提交。当前接管实现依赖 Linux 的 `/proc/self/fd`；macOS 和 Windows 会明确拒绝场景导入，直到实现并验证对应的安全句柄方案。上述保护不构成对不可信同用户进程的完整沙箱。

为避免在身份检查后删除被替换的目录项，接管暂不删除成功导入的 staging GLB 和资源临时项。重复导入相同资源时，临时项也可能是独立副本，磁盘占用会持续累积；失败、取消或恶意替换也可能留下临时项。恶意占用最终哈希名称时，重试可能报告资源损坏。安全的残留清理和恢复机制仍待实现。

Linux worker 重启时仅清理有完整租约、原创建进程已退出且文件身份匹配的受控普通临时文件；活进程文件、未知旧 tmp、链接、未完成登记和已提交资源保留。非 Linux 暂不自动清理。

## 范围和验证

已实现能力与未实现范围分别列在下文。能否从几何推断出的事实必须有依据；限位、类型或其他必要信息不可靠时请求用户补充。不同源文件可加入同一个项目场景；添加、替换、取消和失败保留语义见 [前端与交互](frontend.md)。

当前实现支持装配导入、局部位姿、对象子树删除、世界保守包围盒和对齐原点；删除只改变场景，不修改原始 STEP 或 GLB。解析圆柱面只作为带单位的局部几何候选，记录局部轴线上一点、单位方向和米制半径；每个几何最多保留 64 项、每次导入最多 4096 项，超出会标记截断。`scene_get_cylinders` 分页读取候选，`scene_compare_cylinder_axes` 按当前版本比较世界轴线的角度、偏距和半径差。轴向正负不代表运动方向，比较结果也不能推断连接关系、关节类型或运动限制。用户可明确指定父子对象、关节类型和必要轴线，保存草稿并在专用入口确认；相关对象变化后候选会标记过期或失效，限位仍为未知。网格简化、完整几何修复、运动仿真和 URDF 导出尚未实现。世界包围盒由局部边界的八个角变换得到，是保守近似；对齐原点将最小角移动至世界原点；非叶对象、缺少可信变换信息或包含缩放的层级会被拒绝。GLB 使用 glTF 的 Y-up，前端通过外层旋转恢复 Z-up。复杂单位、工业样本和平台兼容性仍需验证。

`scene_measure_distance` 可只读重解析当前项目中两个几何叶对象各自已授权的 STEP，校验源哈希和场景 revision，应用当前 Z-up 世界刚体位姿后返回 OCCT BRep 算法的 `shapeDistanceM`。返回值受 CAD 算法和几何容差影响，不是数学上无误差的距离；完全包含、交叉和接触都可能得到零。`surfaceDistanceM` 固定为 null，`collision` 固定为 unknown；`innerSolution` 为真时两个点也为 null，不将内部点误称为表面接触点。真实测试覆盖重复实例、不同 STEP、父级旋转、编辑后位姿、相离/接触/交叉/完全包含、源变更/缺失及运行中取消。复杂曲面、退化几何、大型工业模型和跨平台表现尚未充分验证。

GLB 编码使用紧凑的浮点与索引数组，分配每个面的数组前按大小限制检查；256 MiB 限制是资源大小限制，并非进程总内存上限。OCCT 网格生成和 GLB 缓冲仍需额外内存，复杂模型可能消耗大量内存。测试覆盖合成 STEP 的层级、实例、颜色、单位、盒体法线和圆柱侧面法线，以及内存 XCAF 的正负尺度；不代表已验证工业 STEP 的复杂样式、镜像与性能。业务 Python 包依赖的第三方几何库仍包含原生代码。

显示网格质量参数和 BRep 简化没有接入生产；历史临时网格 PoC 不作为当前能力或验收依据。

### 场景资源的读取与显示

后端只向桌面进程返回已授权资源的项目身份、大小与媒体类型；桌面不再接受并重新打开后端返回的文件路径。Linux 启动时固定数据根目录句柄，并通过 `/proc/self/fd` 与 `O_NOFOLLOW` 逐级打开项目、场景和资源目录以及资源文件。读取器按声明大小（最多 256 MiB）读入独立缓冲，在发送前验证 SHA-256；`GET` 和 `HEAD` 都需要通过校验。资源校验后不再重读源 inode，因此路径替换、父目录替换及同 inode 内容改变不会把未经校验的数据交给前端；取消与退出会关闭相关句柄，退出期间活跃读取保留根句柄直到结束。

此实现为 Linux 专用：当前缺少 macOS 和 Windows 上经实机验证的目录句柄方案，因而这些系统的场景资源读取明确失败，不能宣称已跨平台支持。每次请求最多需缓冲 256 MiB，协议响应可能额外复制数据；当前最多同时执行两个读取，复杂大型场景的内存和性能需进一步验证。上述措施确保返回内容与授权哈希一致，不代表阻止了同用户其他进程修改应用数据或对应用进行拒绝服务。

桌面启动时固定数据根目录句柄，并将该句柄的设备号和 inode 作为身份传给后端；场景目录创建、产物接管及 Python worker 均对实际打开的根目录重新核对身份。运行中切换数据根符号链接或替换其实际目录时，场景导入会拒绝，不向新根写入。设置、凭据、会话与包使用启动时解析的规范路径，避免之后更换配置链接导致重定向；但 SQLite、普通设置和会话文件并未全部改为目录句柄访问，若规范根本身被同用户进程替换，不能宣称全应用数据已得到相同隔离。

Linux 桌面初始化也使用目录句柄：从已有的规范祖先逐级打开或创建数据根，并在固定的根句柄下创建应用子目录，再将该句柄交给资源读取器。显式指定的数据根符号链接在启动时解析并固定其当时的目标；启动期间祖先或根目录被替换时，路径与句柄身份检查会拒绝继续。该机制不证明在首次启动、固定身份之前用户指定的链接未被同用户其他进程预先改动；这种场景需要可信的外部身份记录或禁止符号链接。非 Linux 启动路径尚未实机验证。

- `tests/backend/scene/scene_workflow.test.ts`、`scene_store.test.ts`、`scene_store_race.test.ts` 和 `scene_joints.test.ts` 覆盖场景工作流、版本提交、竞态和关节；`import_chat_concurrency.test.ts`、`scene_cancel_workflow.test.ts` 覆盖导入互斥与取消。文件均位于 `tests/backend/scene/`。
- `tests/packages/scene_runtime.test.ts` 与 `runtime.test.ts` 覆盖 Runtime 生命周期；`npm run test:scene` 还运行 Python 几何和场景专项测试。真实 Python/OCP、STEP 样本和 Electron 环境要求见 [测试与验收](testing.md)。
- `tests/integration/scene_import_ui.test.ts`、`scene_project_concurrency.test.ts` 覆盖界面导入及项目隔离；工业模型、跨平台和资源占用仍需按实际目标环境验收。
