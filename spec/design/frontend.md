# Dai 前端与交互目标设计

状态：目标设计；现有页面以工作树为准。相关职责见 [后端与数据](backend.md)、[场景 Runtime](scene-runtime.md) 和 [Package 与 Skill](packages.md)。

## 项目和会话

创建项目时填写名称、选择模式，可选择工作文件夹；未选择时由 Dai 在系统 Documents/Dai 下创建。不同项目允许选择同一文件夹，前端依稳定项目 ID 选择和恢复，不能按目录路径合并项目。不同模式对应不同系统提示词和 Skill；会话继承项目模式，聊天栏不独立切换模式。

启动应用只显示轻量项目列表，不提前请求所有场景或启动全部 worker。点击项目后加载该项目唯一的共享可视化场景；选中聊天后恢复其历史和草稿。切换同项目会话保持当前场景；新会话历史独立，分叉继承分叉点历史但不复制场景。切到其他项目先解除旧订阅，防止旧项目迟到的资源或事件覆盖当前界面。

## 场景搭建

项目中可以选择或拖入位于项目目录内外的 STEP；选择文件与成功导入是两个状态。用户已有场景时，明确意图则执行添加或替换；意图不明时询问添加、替换或取消。替换必须等新数据校验和提交成功才刷新画面；失败、取消、部分不可显示及源文件失效均显示真实状态，不把失败结果呈现为已保存。

视口、对象树和 Agent 读取同一已提交场景；场景可能包含多个来源与实例。手动编辑与 Agent 命令经过同一提交入口。确认关节候选需要呈现依据与不确定性；对象或变换变化使已确认内容失效时应提示重新验证。模型能力不足时不假称模型看到了画面或可靠推断出物理属性。具体删除/替换确认、撤销深度和关节编辑交互另议；URDF 导出不在本轮设计。

切换项目、刷新或重启时，恢复和错误反馈不能显示其他项目的旧模型；源 STEP 缺失时可显示已保存资源但需提示受影响的计算能力。视角和选中项等界面状态是否跨会话或重启保存待定，不将它们与共享场景的几何状态混为一谈。

## 聊天、设置和扩展

保留实际可用的流式聊天、Markdown、停止、草稿、图片能力提示、模型及推理档选择、登录、窗口和主题等行为。工具/用户询问有明确的等待、回答、取消和异常状态；切换或退出不能使回答失去目标，也不能让用户看到未提交的场景。

扩展区域使用 Pi package 和 Skill 概念，支持安装、启停、来源、错误和包内资源状态；MCP 只在提供它的 package 上展示，不提供独立新增 MCP 服务入口。Skill 支持新建、编辑和完整目录导入；包内 Skill 只读，用户可以自行创建或导入新 Skill，直接复制入口尚未实现。各模式加载对应提示词和 Skill；安装、启用、会话加载和实际连接是不同状态，详见 [Package 与 Skill](packages.md)。

机器人模式目前展示演示设备和界面，不代表已经接入真实物理设备；后续能力按实际设备需求设计和验证。
