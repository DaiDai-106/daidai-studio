# 测试与验收

本文记录测试入口、验收范围和具体运行结果。任何一次测试结果以当次命令、环境、通过/失败/跳过数和产物为准；旧文档中的历史通过数量不能作为当前结果。

## 先验证测试系统

模块设计和实现前检查 Node/npm 与依赖、构建、测试发现、测试对端、隔离临时数据和退出码；报告所有失败、跳过与环境缺失。不同测试能力单独验证，不能把 mock 数据的 UI 测试等同于真实几何，也不能把跨平台构建配置等同于目标系统运行。

`npm test` 执行构建和 Node 测试，并报告实际用例数和跳过数；空测试、没有通过用例或进程未产生结果都会失败。`npm run test:scene` 使用 `DAI_SCENE_TEST_PYTHON` 指定的解释器（未指定时使用用户主目录 `~/.dai/python/scene` 中的场景环境），先检查 OCP/VTK，再运行 Python 几何测试及 Node Runtime 与场景工作流测试；解释器或依赖缺失、全部跳过或预期失败时直接失败，不把未执行视为通过。

`npm run lint` 使用 Biome 检查 TypeScript、JavaScript 模块及相关资源；Python 开发环境安装 `pyproject.toml` 的 `dev` 可选依赖后可运行 `npm run lint:python`，由 Ruff 检查 Python 格式和基础错误。检查范围见[代码规范](../code_style.md)。

当前测试覆盖项目与分叉、图片/思考流、命令确认、包内 MCP、Skill、真实 STEP 导入、重复实例、删除、变换、对齐、精确距离和重启恢复。几何修复、完整部分失败诊断和运动链仍需按实际功能补充验收；视口截图没有产品入口，不计作已实现能力。

网页预览回归使用本机 HTTP/HTTPS 对端，不依赖外站。HTTPS 集成测试需要 OpenSSL 生成临时证书，先验证默认拒绝自签名证书，再仅在测试进程中信任本次证书，覆盖跨来源跳转、脚本、WSS、前进/后退、HTTP 降级阻止、权限拒绝和主应用接口隔离。生产代码不跳过证书校验。Google 等外站的实际加载须另行报告，不能用本地 TLS 测试替代公网连通性验证。

真实 STEP 测试应明确样本来源和可分发许可；生成的 STEP 与手工占位文件不是同一类证据，额外工业样本按实际情况报告。Electron 集成测试需要可用的图形显示环境；不可用时报告阻塞，不虚报通过。模型和 MCP 测试使用本地对端，避免消费用户账号。

- 项目主页及项目切换以项目 ID 区分；没有活动聊天时，各已实现的工作区仍可见和操作。会话按创建时间倒序列在所属项目下，切换或分叉不重置共享场景。
- 待回复询问、运行任务及草稿在切换、关闭和错误时保持目标正确；异步旧项目响应不得覆盖当前视图。实际保存失败应有反馈，不能凭渲染状态声称数据已保存或备份。
- Coding 验证左侧项目、中间 AI 对话、右侧功能区；场景和机器人验证当前中间功能区、右侧聊天的布局。Coding 右侧与内部导航分别展开/收起、拖动宽度、在文件和变更间切换时，内容标签及聊天上下文保持正确，展开默认各半。预览收起时不可遮挡聊天、设置或弹窗，恢复后显示正确项目；关闭标签释放资源。
- 在宽、窄窗口及浅、深色主题下验证面板、键盘操作和可访问名称；设置往返保留上下文。机器人演示清楚标记，Coding 的文件树、只读高亮与 Git diff 按 [Coding 工作区](coding_workspace.md) 验收，未实现能力不作为已完成验收。
- 工作台重排后回归场景导入、提交、恢复、会话、权限及插件/Skill 流程；涉及真实几何与设备的验证分别报告，不能以 UI mock 代替。

网页标签与预览的专项场景见 [Coding 工作区](coding_workspace.md)；尤其需要验证来源隔离、项目切换与预览视图生命周期。

## 分层验收

- **Pi 与会话**：固定 SDK 版本、普通聊天、新建和分叉、历史恢复、流式终态与持久化时序、停止和错误。不同项目即使使用相同 cwd 也不能混淆身份或模式。
- **项目和场景**：启动不预加载所有场景；点击项目恢复共享场景，选中会话恢复各自历史。A 导入、B 添加后 A 可见；分叉不复制场景；跨项目隔离、删除会话不删除项目场景。
- **文件与提交**：项目外 STEP 授权；缺失、移动、变化、重新定位；添加/替换/取消、部分失败、版本冲突、worker 故障、提交前后取消及重启恢复。不可自动重放副作用，不能清理恢复必需资源。
- **Runtime 和几何**：按需启动及释放、进程终止和异常传播；真实 STEP 的层级、颜色、实例、单位、几何和性能对照；用户界面和 Agent 操作通过同一提交服务。
- **扩展与 Skill**：真实 Pi package 的安装、发现、加载、禁用和错误；Skill 目录、模式注入、编辑与附件；以本地测试服务验证由包 Extension 注册 MCP、连接、取消和来源，并验证独立 MCP 配置不能绕过产品入口。环境变量、凭据和终端 UI 的兼容边界必须真实测试。
- **前端和打包**：Electron 中的项目、聊天、场景刷新、询问/取消、错误和重启；Python 与原生依赖在每个目标系统中验证。不同平台没有运行时不得标为已通过。

URDF 导出本轮不设计、不作为验收条件。每项功能只有代码、真实边界测试和可复现运行都通过后才标记为实现；测试不足、样本缺失及平台未验证应明确记录。

发布前还需结合实际环境验证复杂工业 STEP、处理性能、目标平台的 Python 依赖以及第三方扩展交互；机器人演示界面的测试不能代替真实设备接入验证。
