# 插件与技能中心

本文记录当前 Coding 版本的实现，基于 Pi SDK 1.5.2。包格式、安装和技能边界见 [Package 与 Skill](packages.md)，公司目录格式见 [公司目录接入](../company_catalog.md)。

## 职责与目录

市场来源、分发来源和运行宿主是三个独立维度：

| 维度 | 当前支持 | 职责 |
| --- | --- | --- |
| 市场 | Pi Catalog、公司内部 | 搜索、详情和版本发现 |
| 分发 | npm、Git、本地目录 | 复用 Pi SDK 下载和维护包 |
| 宿主 | Pi、Desktop | 决定安装空间、资源加载和变更影响 |

两个市场都可以提供 Pi 或 Desktop 包。第一版不接受混合两类宿主资源的包，需拆分发布。市场展示的类型用于路由，安装后必须校验实际清单；不会根据包名猜测宿主。

```text
数据根/
├── catalog/
│   ├── sources.json         公司目录地址
│   ├── origins.json         市场条目与安装记录的关联
│   └── git/                 公司目录裸仓库，按地址哈希区分
├── agent/
│   ├── skills/              用户技能完整目录
│   └── packages/
│       ├── settings.json    Pi 全局配置
│       ├── disabled.json    有停用变更时保存
│       ├── npm/、git/       SDK 管理的全局安装内容
│       └── modules/<模块>/
│           ├── settings.json
│           └── .pi/               SDK 管理的模块安装内容
└── desktop/packages/
    ├── settings.json        Desktop 全局配置
    ├── disabled.json        有停用变更时保存
    └── npm/、git/           SDK 管理的桌面安装内容
```

本地目录来源由 SDK 引用原目录，不承诺复制到上述安装空间。用户项目中不创建 `.dai/`，包服务的托管 cwd 不使用用户项目路径。Pi 全局和模块分别映射 SDK 的 user/project 作用域；Desktop 的 project 视图固定为空，不读取遗留模块配置。

应用启动时将模块旧的 `workspace/.pi/` 整体迁移到模块根下的 `.pi/`，本地相对来源先转为原位置的绝对路径。新旧安装目录同时存在时拒绝覆盖；旧 `workspace/` 只在为空时删除。

`catalog_storage.ts` 是市场目录路径的唯一所有者。应用启动时，若新 `catalog/` 不存在，将旧 `agent/catalog/` 整体搬迁；已有新目录时不覆盖、不合并。旧混放 Desktop 包需移除旧安装记录后重新安装，目录迁移不承担包配置迁移。

| 代码 | 职责 |
| --- | --- |
| `catalog_storage.ts` | 共用目录、来源文件、进程缓存和旧目录迁移 |
| `catalog_sources.ts` | 两个市场的查询、详情与安装前复核；复用同一存储实例 |
| `company_catalog.ts` | 公司地址校验、裸 Git 目录读取及并发请求合并 |
| `catalog_service.ts` | 共用后台任务、来源关联和最近加载诊断 |
| `package_manifest.ts` | 一次解析清单中的宿主和资源，统一混合资源校验 |
| `package_service.ts` | 共用 SDK 安装代码、各宿主的配置与操作队列、来源规范化 |
| `skill_service.ts`、`skill_handlers.ts` | 用户技能编辑与包内有效技能查询 |
| `src/desktop/main/themes.ts` | 仅从 Desktop 安装快照读取声明式主题 |

未带 `src/` 的代码路径均相对于 `src/backend/extensions/`。

## 目录查询与缓存

Pi 市场使用 npm 的 `pi-package` 搜索，收录和排序可能与 Pi 官网不同；界面保留官网链接和手动安装入口。公司目录支持 HTTPS JSON 或使用系统 Git 凭据的 HTTPS/SSH 仓库。

查询、详情和版本复核不执行扩展。HTTPS JSON 请求有超时和响应大小限制，不跟随重定向。Git 目录仅获取裸仓库并读取 `catalog.json`，不检出工作树；安装前复核绕过元数据缓存，因此 Git 层仍需合并对同一裸仓库的并发请求。

搜索和详情结果只在进程内缓存：有效期五分钟，最多 100 个缓存键；同键请求合并，刷新失败可显示旧结果并明确提示缓存。重启后不提供持久化元数据回退。`catalog/git/` 中的裸仓库不是离线批准安装的依据。

npm 最新版本信息与完整历史分开读取。最新版本响应上限 1 MB；历史及 README 补充响应上限 8 MB、超时六秒。补充失败不阻断最新版本详情。安装前重新读取所选版本并验证 `pi-package` 声明，不依赖完整历史或旧缓存。详情重新读取会绕过缓存。

兼容性仅显示“未验证”和“不兼容”，不提供没有验证机制支撑的认证状态。资源筛选仅针对当前已加载页的已确认声明，约定目录包的类型可能保持未知。

## 安装、启停与加载

所有包写操作经 `catalog.*` 任务入口，共用任务列表、进度回调和界面。每次仅允许一个市场任务运行，任务在当前进程最多保留 100 项；重启后不恢复历史任务，不伪造安装百分比。

手动安装选择 Pi 或桌面类型；市场安装根据重新复核的条目选择宿主。来源在任务登记前统一处理空白和 `~/` 路径，拒绝带密码的 HTTP/SSH URL，避免任务记录保存凭据。SSH 用户名不作为密码拒绝。

每个宿主使用独立的包队列；Pi 各模块因共享全局设置而共用队列。安装、配置提交和启用在同一次队列操作中完成，新会话不能读到两步之间的停用状态。所有 SDK 配置写入在返回前等待 `SettingsManager.flush()`。已启用状态没有变化时不重复写禁用文件。

Pi 变更前检查并释放相关会话：全局操作影响所有模块，模块操作影响所属模块；SDK 更新可能同时影响全局与当前模块。运行中的相关会话需先停止，下次发送消息重建 Agent。Desktop 操作不使 Agent 失效，也不触发桌面主题对 Pi 任务的重复刷新。

安装、启用、扩展加载和工具执行是不同阶段。最近加载诊断按模块、作用域和来源区分；同来源的全局与模块记录不能互相冒充加载成功。同包任一扩展加载失败保留包级错误，下次该范围成功加载可恢复。纯 Skill 包没有 Extension 加载记录时，不据此判定技能是否生效。

安装清单由 SDK 配置和实际文件决定，市场缓存不保存第二份安装清单。`package.list` 提供不依赖市场配置的宿主安装快照；市场或来源关联损坏不影响 Desktop 主题发现。查询快照不补写宿主标记或空资源过滤器。

## 界面与技能

插件中心提供“发现插件、已安装、我的技能”三个页签，共用深浅主题和基础组件。发现页只保留两个实际市场。详情支持概览和包含内容，版本统一通过顶部下拉选择。

搜索支持防抖、分页、刷新、缓存提示和来源独立失败。异步列表与详情丢弃过期响应，任务终态不被迟到的进行中快照覆盖。详情关闭后恢复原卡片焦点，支持键盘关闭；Markdown 不执行 HTML，不直接加载远程图片。

已安装列表区分宿主、来源和作用域，提供安装、启停、更新与移除。桌面插件仅支持全局；Pi 支持全局和模块，当前界面只开放 Coding。scene/robot 标识仅保留给模块隔离，不恢复旧业务实现。

市场关联的已安装插件更新前强制刷新目录并确认目标版本，沿用原宿主、作用域和启停状态；目录不可用时不使用旧缓存更新，安装来源变更到不同包时需用户手动检查。手动固定 npm 版本和本地目录不自动升级，提示原因。已完成或失败的任务提示可关闭，进行中的任务不可关闭；关闭不删除任务。更新并非跨文件事务，失败后应检查实际安装状态。

用户技能支持新建、编辑及完整目录导入；包内有效技能只读。技能归属包含来源和作用域，详情不会将模块技能显示为同来源的全局技能。Desktop 详情不查询 Pi 技能。没有有效的内置技能来源，协议仅保留 user/package 两类。

桌面主题的 JSON 协议、校验和资源暂时缺失时的选择恢复规则见 [Package 与 Skill](packages.md)。

## 验证与限制

- 后端覆盖目录查询、缓存、公司 Git、独立安装空间、真实本地 npm/Git 安装更新、任务、会话并发、加载范围和技能归属。
- Electron 回归覆盖市场布局与详情、技能编辑恢复、主题安装启停、重启恢复及主题回退竞态。
- 模型交互使用本地对端，目录界面使用测试 HTTPS 服务；私有 GitLab 认证、生产代理和跨平台安装仍需真实环境验收。
- Pi 交互桥支持 confirm/select/input/notify，终端专属界面不自动兼容桌面。不装配 MCP 连接器，不开放任意 React/CSS/脚本桌面插件 SDK。
- 第三方 Pi Extension 在宿主进程运行；npm/Git 安装可能运行依赖脚本，文件工具检查不构成扩展沙箱。
- SDK 更新与多个文件写入不承诺事务回滚。安装没有可取消句柄，正常退出等待安装结束。

运行入口与环境要求见 [测试与验收](testing.md)。
