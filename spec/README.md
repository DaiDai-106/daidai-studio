# Dai 开发规范

更新：2026-10-26。状态：第一阶段清理、CAD 标准 stdio 插件、Harness 成功结果驱动的显示接管及前端只读查看已接入。Runtime 已按设置、项目、会话和 MCP 拆分请求处理，保留唯一队列和原有恢复、取消及释放顺序，不另建执行器或 adapter。 产物校验按清单、GLB/面映射、特征缓存拆分，保持原入口；聊天条目/用量转换与统一事件状态分开，内置授权检查保持不变。

当前新增：独立 alignment-mcp 提供包围盒查询、角点归零、参考系对齐和绕轴旋转。定位保存为绝对平移与四元数，旧平移文件/历史可恢复。场景搭建复用 Pi read，无逐次确认；CAD 导入可导出离线对齐参照，每个 Run 结束释放文档，后续定位不依赖原 STEP 仍存在。

本次实现覆盖可读产物、read、完整整机定位和前端旋转回显，并区分已有场景问答、临时原始几何查询与显示发布；视口截图、将前端选中项发送给模型仍是后续能力，不宣称模型自动看见画面。

场景产物与定位保存在用户数据根的项目目录，同项目同 STEP 共享、聊天独立。旧项目内产物不自动迁移或删除；存储与授权边界见 [后端设计第 14 节](backend_spec/backend.md#14-用户目录场景存储)。

第一阶段目标：用户选中项目中的 STEP，通过对话让模型决定 CAD MCP 调用；工具产生可显示资源后，由桌面接管，依据 Harness 的成功工具结果通知前端加载。

## 已确认范围

| 保留 | 本轮删除与重写范围 |
| --- | --- |
| 项目、多对话、草稿、归档、恢复、产品层删除、移除项目 | 重组 Node 后端入口、模块与请求分发 |
| 模型目录、登录、凭据与设置 | 移除 modeling、assembly 插件、原生程序及专用计算库 |
| 窗口、托盘、单实例、主题、快捷键、三平台构建配置 | 移除场景编辑、运动学、配合、URDF 编排与相关前端入口 |
| 一个共享 SQLite、一个 pi-durable Harness | 移除依赖 SceneHost 的 CAD 桌面专用绑定 |
| CAD 全部 12 个工具及真实几何能力 | 重构 CAD 类型、协议边界、内部结构和注释 |
| 内外部 MCP 配置、发现及自定义 Skill 基础能力 | 将内置 Skill 收敛为选中 STEP 的导入与显示 |

CAD 的精确特征、拓扑拆分、属性、测量等能力继续保留；第一份 Skill 不承担它们的全部业务流程。前端支持查看、选择及显示已保存的整机定位，暂不增加颜色、位置、分组或关节编辑面板。物理仿真、云同步、远程主机、Coding Agent、子智能体均不在本阶段。

## 工程约束

- 每个插件自行提供标准 stdio MCP 服务端；桌面仅通过 pi-mcp 连接、发现和调用，不保留进程内服务特例。内置仅表示随安装包分发。C++ 实现几何功能，官方 TS SDK 负责薄协议封装。
- 复用 pi-durable 的 Conversation、ToolTask、订阅、usage、取消、压缩和恢复；复用 pi-ai 认证与模型能力、pi-mcp 客户端、官方 TypeScript MCP 服务端 SDK。
- 数据契约先于业务实现。跨边界使用运行时 Schema，TypeScript 类型由同一 Schema 推导；内部用明确的值类型。
- 每个模块有集中的类型定义及清晰入口，普通函数优先。只抽取已有的重复职责，不预建 DI 容器、插件市场、工作流引擎、消息总线或通用任务账本。
- 注释说明用途、所有权、单位、坐标空间、失效条件和必要取舍；不逐行复述代码，不用长注释解释复杂的补丁。
- C++ 保留 include/src；沿用 daidai 命名：类型 PascalCase、函数 camelCase、文件和字段 snake_case、私有成员 `_` 后缀。使用现有 clang-format，前端及 TS 使用 Biome。
- CMake 使用已安装依赖和标准 find_package；无构建时下载、第三方源码补丁或向依赖注入选项。
- 不删除用户数据、原 STEP、凭据或聊天历史。旧业务产物保留文件，迁移策略见后端文档。
- 测试覆盖真实边界与失败行为；自动测试使用本地模型协议对端，不消耗个人付费 API。跨平台配置通过不等于目标系统实测通过。
- 测试与辅助程序统一放在仓库根目录 `tests/`：`backend/`、`renderer/`、`shared/` 按模块分类，`mcp/` 和 `cad/` 覆盖插件边界，`cad/native/` 保存 C++ 测试，`integration/` 覆盖跨模块流程，`fixtures/` 与 `support/` 保存对端及辅助代码。`src/` 和 `resources/` 只保存应用及插件实现；TypeScript 测试入口仅扫描 `tests/**/*.test.ts`，C++ 测试沿用 CMake/CTest。

旧的单体 PRD 与历次开发流水账已退出规范体系。后续只维护上述各模块设计和本入口中的范围、实施状态。
