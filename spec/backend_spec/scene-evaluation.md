# 场景朝向评测

基线版本：使用 `scene_inspect`、单方向对齐和视口截图之前的实现。现有脚本模型测试只能验证调用链，不是模型朝向判断的成功率。仓库目前没有可复现的真实模型朝向评测结果；不要将已有 CAD 工具调用报告当作该基线。

代码基线（改造前检查，按能力存在与否记录，不作为模型准确率）：

| 能力 | 基线 |
| --- | --- |
| 对象层级 | 已保存目录按页读取；没有统一的场景摘要工具 |
| 仅对齐一个方向 | 无专用接口；参考系对齐同时要求上方向和前方向 |
| 自动读取视口 | 无；可以由用户在聊天中手动附图 |
| 明确的轴角旋转 | 已有 `alignment_rotate`；原生测试覆盖坐标和枢轴 |
| 真实模型自动摆正成功率 | 未测量；需要使用固定数据、模型和可审计轨迹运行 |

固定几何回归样本由 `out/native/cad-core-tests --write-fixture <路径>` 生成，包含命名装配、两个箱体实例和一个圆柱。`tests/alignment/native.test.ts` 验证单方向的 90 度、180 度、枢轴及实例变换；`tests/integration/scene-inspection.test.ts` 验证摘要和图像传递。它们是执行链基线，不能验证语义识别。

每次评测记录代码版本、模型及配置、STEP 的 hash、初始 placement、用户输入、工具轨迹、最终 placement、耗时和输入输出 token。对每个样本重复至少三次，保存原始记录；对存在歧义的样本由人工评估是否合理澄清。图片样本记录实际传入模型的视图与拍摄版本。

| 场景 | 请求 | 验收 |
| --- | --- | --- |
| 已知轴角 | 绕世界 X 轴和原点旋转 90 度 | 实际位姿符合旋转；不额外落地 |
| 已知上方向 | 模型 Y 轴朝世界上方 | Y 映射到 +Z；未要求正面 |
| 已知底面 | 将指定平面作为底面 | 该面法向对应向下；参考属于当前对象 |
| 完整参考系 | 指定上、前与锚点 | 两个方向和锚点满足目标 |
| 对称或缺少语义 | 自动摆正 | 不能从现有证据确定时说明候选并澄清 |
| 只读分析 | 分析设备当前朝向 | 不改变 placement |
| 视图参考 | 按给定图片摆放 | 结合实际图像和几何；有歧义时澄清 |
| 版本变更 | 使用过期 revision 操作 | 拒绝旧操作，重新判断而不盲目重放 |

记录方向正确率、误操作率、合理澄清率、工具调用数和耗时。单方向题只评价方向与规定的枢轴，不评价未约束的正面。带图片和不带图片分别统计。测试数据与评测轨迹需去除用户私有模型及凭据后才能共享。

## 型钢样本：工具链回归

以用户提供的型钢 STEP 临时副本测试，源文件 SHA-256 为 `a61a79d8ec01692539c51792aa2a7d2a8dd5fe642084b1632f97788a6f5eedae`。`tests/integration/steel-alignment-real.test.ts` 中的脚本模型使用人工从该场景确认的源方向和地脚尺寸；测试不代表真实模型能独立从图像识别特征。

两次本地运行：首次导入、生成预览和对齐总计分别约 120.1 秒、83.1 秒；预览发布后，观察、参考系对齐、低处对象排序、四个地脚特征查询和落地分别约 3.7 秒、2.8 秒。各次共 11 次工具调用、12 次脚本模型请求，Bash 0 次。四个已确认地脚的接触面均到 Z=0（误差小于 1e-6 米），落地保留 X/Y 与旋转。耗时依赖机器和负载，不是线上真实模型的延迟承诺。

上一轮实际模型轨迹约有 63 次工具结果、15 次 Bash、15 次视口截图和 56 次模型生成任务；两个样本的决策方式和运行环境不同，不能将调用数或耗时直接当作真实模型性能提升比例。真实模型的图像判断、候选选择与耗时仍需重复评测。

在 Linux 构建原生组件后，可用以下命令复跑；测试会将 STEP 复制到临时目录：

```sh
DAI_CAD_REAL_STEP="/path/to/steel.step" \
DAI_CAD_TEST_WORKER="$PWD/out/native/dai-cad-worker" \
DAI_ALIGNMENT_TEST_WORKER="$PWD/out/native/dai-alignment-worker" \
node --experimental-strip-types tests/integration/steel-alignment-real.test.ts
```
