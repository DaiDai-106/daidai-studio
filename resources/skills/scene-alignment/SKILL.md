# 整机朝向与定位

本技能处理整个已发布模型的刚体定位，不改变原始 STEP、显示网格或零件之间的相对位置。使用最新 `scene-context.currentDisplay` 的 `importId`、`placement` 和 `placement.revision`；未发布显示时说明缺少目标，不使用历史 ID 或为普通定位重新导入。`files.placement=null` 表示尚无定位文件，初始姿态以 `currentDisplay.placement` 为准。

约定：长度单位米、角度单位度、右手系、世界 Z 向上；四元数为 `[x,y,z,w]`。世界轴和原始模型轴属于不同坐标系；`space="model"` 的轴与枢轴是原始模型坐标，并非已旋转后的局部坐标。子装配的局部变换不能当成整机变换，恒等旋转也不能证明设备的实际朝向。

## 先确定目标和证据

- 用户只要求分析或解释时，只进行查询并回答，不修改定位。用户要求旋转、摆正或对齐时，按其明确的目标执行；“归零”“落地”“朝上”和“朝前”是不同目标，不把位置变化说成朝向已经正确。
- 用户要求分析朝向或自动摆正，而已发布对象目录与 `read` 可用时，先按 `scene-building` 读取最新对象目录各页，再针对候选对象按需查询边界和保存特征；即使本轮刚导入，也读取发布后的目录。整体包围盒、历史对话、一级结构或图片不能替代此步骤。目录不可用或读取失败时如实说明，不声称已检查或因此自动重导。
- 综合用户提供的方向、图片以及实际查询到的对象名称、层级、位置与几何参照，给出有依据的候选方向。指出证据来自哪里、属于哪个坐标系，并区分观察和推断。最长边、坐标正负、单个平面或局部变换不能单独证明物理上下或正面；截图有透视和遮挡，不能当作精确坐标。
- 用户要求自动摆正且证据足以确定所需变换时，主动调用工具；缺少影响结果的方向、旋转或锚点时，说明已检查的信息与候选方案，询问具体缺失项。只要求朝上时不自行指定未要求的正面；多种旋转都可能满足目标时不要猜。不得依靠假设声称已确认设备姿态。
- 如果用户已明确指定旋转轴、方向、角度和枢轴，或已确认具体方案，直接执行；单纯旋转或最小角点归零无需为了执行而读取目录。对于“世界 X 轴 +90°”，轴为 `[1,0,0]`，正角按右手规则，世界坐标轴穿过世界原点；用户指定其他枢轴时使用指定点。关键参数有歧义时先澄清。

## 选择工具

- `alignment_get_bounds`：查询整机或指定保存对象及其子对象的世界显示网格包围盒。它不是精确 B-Rep 边界，显示缺面可能影响结果。
- `alignment_align_min_corner`：保持当前旋转，将显示包围盒最小角点移到原点。它只确定位置，不证明底面或设备朝向正确。
- `alignment_rotate`：按明确的轴、角度、枢轴和世界/模型空间执行相对旋转。
- `alignment_align_frame`：将明确的来源朝上和朝前方向映射到目标参考系，并按指定锚点放置。`sourceUp`、`sourceForward` 必须有依据；CAD 特征使用当前保存场景中的有效 `objectId`、`featureId`，反向时显式设置 `reverse`。特征为对象局部坐标，工具负责装配实例变换。目标世界坐标系是约定，不证明设备自身方向；缺失正面方向时不要编造。
- `anchor="reference"` 使用提供的来源点或有效 CAD 特征；`min_corner` 与 `bottom_center` 基于旋转后的显示网格。根据用户目标选锚点，不暗中换成其他锚点。

## 版本、失败与结果

每次修改提供最新 `expectedRevision`。多个依赖操作须逐次等待桌面保存后的新版本，才能发起下一次；不要预先用同一旧版本生成多个修改调用。若能明确表达目标，可用一次参考系对齐完成朝向与放置。

`SCENE_TARGET_CHANGED` 或 `READ_PATH_NOT_AUTHORIZED` 时使用返回的最新场景，不通过重复导入修复目标；`REVISION_CONFLICT` 时检查当前定位与已完成操作后重新判断。相对旋转结果不明确时先核实，不盲目重放；特征或方向不足时说明限制，不编造引用。

工具计算、桌面保存和视口渲染是不同状态。仅在有实际结果时报告完成，说明应用的旋转、平移、锚点及相关警告；没有视口反馈不声称已确认画面。达到用户目标即停止，不额外旋转、归零或重建显示。
